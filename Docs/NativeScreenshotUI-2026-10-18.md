# Build 53：使用 macOS 原生截圖介面

Windows 截圖鍵及原本被攔截的 ⌘⇧3／4 改用 `screencapture -u -p`。`-u` 啟用系統完成介面，`-p` 使用系統截圖設定。右下角縮圖、標記、裁切、分享與刪除由系統處理；移除自訂縮圖面板、縮圖 PNG 產生與 `qlmanage` 程序。這些參數依本機 `man screencapture` 的公開介面實作，沒有使用私有 API。

`-u` 會忽略輸出檔案路徑，因此不再把圖片截圖導向私有暫存檔。所有圖片截圖遵循 macOS 儲存設定（預設桌面）；用 ⌘⇧5 →「選項」設定位置與浮動縮圖。App 不寫入系統截圖偏好。

只有明確要求截圖後才啟動既有的 FSEvents 觀察器，接收設定資料夾中新建立、具有 Apple 截圖中繼資料的檔案；不列舉既有圖片或輪詢。完成存檔後才自動複製，包含使用者完成編輯的結果。刪除、僅分享或不在該資料夾存檔時，App 不另行改寫剪貼簿。原生縮圖、編輯器與存檔的生命週期由 macOS 管理；App 暫停後僅撤銷自己的待複製工作。

系統存檔不因儲存在暫存資料夾而被視為 App 所有。文字擷取仍保留直接輸出私有 PNG 的流程，完成後清理，且不開啟圖片縮圖或自動啟動一般截圖的 OCR。

## 本機驗證

- 先新增回歸測試，確認舊流程在四種圖片截圖模式都未使用系統介面，並把系統未產生私有檔案誤判為失敗。
- 新的 `SystemScreenshotTests` 八項測試涵蓋原生參數、四種擷取模式、系統存檔與程序退出的兩種順序、只複製一次、暫停後拒絕舊檔、新工作恢復、來源撤銷、編輯器／貼上目標 App 切換，以及保留暫存資料夾內的系統檔案。OCR 仍使用直接檔案擷取。
- 完整 Debug 測試與獨立程序的重複截圖記憶體回歸另行執行；Hosted CI 再驗證 Debug、Release、安裝器、監測工具及完整 App 封裝。

測試使用產生的圖片與私有剪貼簿，沒有拍攝使用者畫面。這些結果不能代替原生縮圖點擊、裁切分享、TCC、實體快捷鍵、多螢幕或跨 Mac 的操作驗收；步驟見 [AcceptanceGuide](../Resources/AcceptanceGuide.md)。CI 與下載安裝結果以對應 run、產物校驗及本機安裝證據為準。
