# Build 54：自製玻璃截圖預覽與先複製流程

使用者實測 build 53 原生浮動縮圖出現後，立即貼上仍可能是前一份圖片或文字。原因是 `screencapture -u -p` 要等 macOS 完成存檔，資料夾觀察器才有可複製檔案；縮短觀察間隔不能解決。

使用者重新選擇最初的自製縮圖，保留「截圖已複製」文字與文字擷取，並要求放大、改善質感及玻璃效果。因此恢復私有 PNG 擷取與自製預覽，不啟動原生完成介面，不更改系統偏好。圖片成功寫入剪貼簿後，才在背景建立有界縮圖；新擷取、關閉功能或政策失效取消舊縮圖，非同步結果核對世代與來源有效性。

預覽由 220×160 放大至 320×248，圖片區 296×172，依比例完整顯示；有成功圖示、主副文字與較大的關閉按鈕。macOS 26+ 且 Swift 6.2+/SDK 支援時使用公開 `NSGlassEffectView`（regular、22 點圓角），較舊建置／系統使用 `NSVisualEffectView` 毛玻璃。遵循系統玻璃輔助使用行為，毛玻璃亦處理減少透明度。滑鼠停留暫停 5 秒消失計時，移出重新計時。沒有新增動畫、固定輪詢或常駐縮圖視窗。CI 明確選擇 runner 已提供的 Xcode 26.3，避免預設 Xcode 16.4 將玻璃分支排除；runtime 最低版本仍是 macOS 14。

一般截圖是私有暫存 PNG；只有預覽接受所有權才延至預覽消失／快速查看結束刪除，預覽失敗、取消或過期結果由擷取端清理。Win+PrintScreen 明確保存桌面圖片，預覽不取得刪除權。系統檔案即使位於暫存資料夾，也不因路徑取得刪除權。文字擷取仍按需啟動獨立 OCR、複製文字與清理原圖，不自動為一般圖片執行 OCR。

## 驗證

測試使用產生的圖片與私有剪貼簿。ScreenshotDeliveryTests 以阻塞縮圖產生器確認縮圖未完成時剪貼簿已是本次圖片，並核對四種模式不含 `-u`／`-p`、暫停後抑制待顯示預覽、保存檔與系統檔案所有權。ScreenshotPreviewTests 恢復複製先於預覽、取消、OCR 不開圖與記憶體預算測試；ScreenshotRuntimeTests 保留政策／來源／權限回歸。

`--render-feature-checks` 僅用產生圖樣離線輸出亮／暗、橫／直預覽，沒有拍攝使用者畫面或讀取一般剪貼簿。完整本機與 Hosted CI 結果以測試日誌及 run 為準；離線輸出不能證明 WindowServer 背景折射、實體快捷鍵、TCC、多螢幕及快速查看互動已驗收。人工步驟見 [AcceptanceGuide](../Resources/AcceptanceGuide.md)。

本機完整 Debug 483 項（含獨立記憶體回歸）通過；其後新增新截圖取代待顯示縮圖的回歸，與預覽／交付測試共 12 項再次通過。Monitoring 6 項通過，8 張離線版面生成成功並檢查亮／暗與直式圖片；plist lint 及 diff whitespace 檢查通過。Hosted CI 使用 Xcode 26.3 執行完整 Debug／Release、Installer／Monitoring、封裝與無 Git ZIP 建置。
