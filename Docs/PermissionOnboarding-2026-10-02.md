# 權限提示與重新開啟（0.5.18 / build 37）

這台 Mac 的 build 36 GUI 已確認：系統「裝置控制和資料取用」開關開啟，AX 檢查成功，按鍵輸出檢查失敗；正常退出並重新開啟同一份 App 後兩項都通過。這證明重開可解決本次狀態，不能據此宣稱已定位 macOS 內部快取原因。

production code 另有兩個造成多個授權提示的問題：第一列在一次操作中連續呼叫兩種原生申請 API；多個其他列的 user-initiated refresh 也會對截圖資料夾做原生讀取，可能連帶要求 Desktop／Documents／Downloads 權限。

修正後每次第一列操作只申請一種尚缺的能力，兩項仍分別以 native check 確認才綠色。截圖資料夾初次讀取只由第八列開始；重新檢查及返回只能重查先前已處理的資料夾。沒有加入權限輪詢、另一份設定視窗或自動重開。

第一列若只取得部分能力，顯示「需重新開啟」，該列按鈕直接正常退出並重新開啟 App，回到同一份權限清單。使用現有終止路徑停止擷取、還原映射並取消舊截圖工作。一次性 launcher 最多等待原本程序 15 秒，不 force quit、不啟動第二個實例；重開後若仍未取得，回到「開啟設定」，不造成重開迴圈。

回歸案例已補入 KeyboardPermissionRequestTests、PermissionChecklistTests。本輪依使用者要求不執行測試套件，只做產生新版 App 必要的 Release 編譯與封裝。

人工驗收：

1. 在本 App 尚未取得截圖資料夾存取時點第一、二或三列；不應連帶跳出截圖資料夾授權。第一列一次點擊不應連續要求 AX 與按鍵輸出兩種提示。
2. 在系統開啟第一列權限後返回 App。若兩項檢查即時通過，應直接綠色；若僅一項通過，按該列「重新開啟 App」，應退出並回到單一設定視窗，重新檢查兩項。
3. 若取消授權或重開後仍未取得，不得顯示綠色或自動反覆重開。第八列仍自行申請目前的截圖資料夾。

本機沒有可用的正式 code-signing identity，仍使用 ad-hoc 簽章。更新可能需要重新核准目前 App；不修改或自動核准 TCC、不以自訂弱化 designated requirement 冒充正式開發者簽章。這仍是正式發布穩定更新的支援缺口。


後續八列完整審查另移除讀取 Driver 狀態時的自動 activation，以及啟動／截圖／Fn 開關／週期檢查的登入項目註冊與移除。第 4 列才註冊登入，第 7 列才送出 activation；其他列只是讀取狀態。內建鍵盤原生 Fn 交換須等登入核准，避免沒有還原入口。

截圖資料夾可讀之前不啟動截圖工作，避免剛開啟第一、二項時順便讀取 Desktop。第八列讀取成功後僅保存「目前 App code hash＋資料夾」的重新檢查範圍，不保存綠燈；下次啟動同一簽章才再做一次原生讀取，新版簽章或新位置不沿用。讀取失敗保持未取得並清除舊範圍。

另加入 App 返回前景的一次性通知檢查（正常 stop 會移除 observer），保留既有五分頁及八列。完整單一 App 現在包成 DMG，內有 App 與 Applications 捷徑；不再提供缺少背景元件的同名 App-only DMG。從磁碟映像直接執行時只提醒先拖入 Applications，不送出背景安裝要求。拖入後首次開啟才處理內含元件。

## 2026-10-03 安裝中断修正

實際安裝 0.5.18 (37) 時，App 已移入 /Applications 後的 chmod 收到 Operation not permitted；TCC 記錄同時顯示 SystemPolicyAppBundles 請求失敗。回復直接 ditto 到受保護的 App 路徑也失敗，留下不完整的 App 與受保護回復快照。這不是鍵盤／Driver 權限未申請造成的提示。

0.5.19 (38) 在 root 暫存區完成 ownership 與 a+rX,go-w，再移動完整 App；回復優先移回完整舊 App，舊交易僅有備份時也先在暫存區重建。恢復流程先核對受保護快照，再檢查目的 App 的 Info.plist，避免不完整目的端阻止回復。新增 App 內容修改遭拒與不完整目的 App 的 regression fixtures；依使用者要求不在本機執行測試套件。
