# WindowsMacBridge 1.0.2（build 66）

## 安裝與使用

1. 點兩下 DMG，先正常結束舊版，把 WindowsMacBridge.app 拖進「應用程式」取代，再開啟。
2. 預設「一般模式」：權限頁逐項列出輔助功能、輸入監控、螢幕錄製與選用的登入時啟動。先核准前兩項；需要截圖再核准螢幕錄製。每次只按一列，核准 WindowsMacBridge 後回來重新檢查；需要時正常結束並重開 App。綠燈必須經本版 App 的原生檢查，不以舊版同名開關作為依據。
3. 本機 App、Terminal 與 IDE 套用完整 Windows 相容快捷鍵：Ctrl+C／V／A／X、S／Z／Y／F、T／W 與文字導覽等。Ctrl+C 一律複製；Terminal 使用 Ctrl+Shift+C 中斷命令。Game 與停用延伸規則的本機 Profile 也保留這四個剪貼簿快捷鍵，且不依賴 ABC／注音切換。遠端 Windows 與 VM 接收原始 Ctrl，交由 Windows 執行複製貼上。總開關關閉與暫停會停止轉換。
4. Win+Shift+S 或 PrintScreen 框選後直接貼上圖片；⌘⇧3／⌘⇧4 也直接複製。成功複製後右下角顯示較大的自製玻璃預覽約 5 秒，滑鼠移入會保留；點圖用系統快速查看放大，關閉後釋放，新截圖取代舊縮圖。首次擷取可能要求螢幕錄製授權；這不是 HID／Root 授權。

一般模式不安裝進階 HID 背景元件、不連線 root XPC、不捕捉 IOHID、不啟用 Driver。App 使用 ad-hoc 簽章，更新可能需要重新核准目前版本；沒有 Apple 公證。不要為此關閉 Gatekeeper／SIP 或重設其他 App 的權限。

## 異常停止後的自動恢復

一般設定顯示「異常停止後自動恢復：已啟用」時，主 App 非預期停止會自動重新開啟並提示。恢復程序平常只等待事件，不固定輪詢。正常按「結束」不會自動重開；權限重新啟動與更新也沿用正常退出流程。

本輪五分鐘內最多自動恢復三次，等待時間依序為 1／3／10 秒。連續失敗或無法確認新 App 已啟動自己的恢復保護時，停止嘗試並顯示提示，可從「應用程式」手動開啟。恢復程序本身停止時，主 App 也會提示保護未就緒。這項保護不替你開啟「開機自動啟動」；登入啟動仍由原本開關控制。

## 六項一般設定

| 項目 | 新安裝預設／操作 |
|---|---|
| Windows 模式總開關 | 開；統一控制 Windows 快捷鍵、Fn／Ctrl 交換、Finder 加強與截圖自動複製。關閉時暫停這些功能、保留子項設定。快捷鍵含複製、貼上、復原、儲存、分頁與文字導覽；Alt+Tab 使用 macOS 原生切換器。唯音守護與登入啟動各自獨立。 |
| MacBook 鍵盤模式 | 關；明確開啟才交換本機內建 Fn／Globe 與左 Ctrl。外接與 UC 虛擬鍵盤不交換。切換前放開所有按鍵。 |
| Finder 檔案操作加強 | 開；Ctrl+X→切資料夾→Ctrl+V 移動、F2 改名、Delete 垃圾桶。Shift+Delete 交由 Finder 原生「立即刪除」確認視窗決定，舊版明確停用永久刪除的設定保留。文字編輯／未知焦點不會盲刪；讀不到 Finder 焦點時 Ctrl+V 只做一般貼上，不搬移檔案。無需 Finder 擴充。 |
| Windows 快捷截圖 | 開；Win+Shift+S／PrintScreen 框選，Alt+PrintScreen 當前視窗，Win+PrintScreen 全螢幕存檔＋複製。⌘⇧3／⌘⇧4 使用相同取消／自動複製流程。 |
| 這臺 Mac 收到的 Windows 鍵 | Command；若實際 Win 發出 Option，改選 Option。不是交換整臺鍵盤的 Ctrl／Command。 |
| 開機自動啟動 | 使用系統原生登入項目，只有明確切換才註冊／移除；不因截圖開關而自動申請。 |

從側邊欄切換權限、一般設定、唯音與輸入法、App 規則、規則預覽與遠端校準；進階模式另顯示診斷。工具列左側可收合側邊欄（⌃⌘S），右側問號開啟使用說明。視窗、選單與控制項跟隨 macOS 外觀，macOS 26 以上採系統液態玻璃，舊系統保留原生材質；亮／暗色及輔助使用的透明度與對比設定由系統管理。

唯音守護與切換熱鍵預設關閉，關閉守護時保留原輸入來源。開啟守護後預設維持唯音繁體；如需英文，用 App 的 ABC 按鈕或切換快捷鍵明確選擇，這個目標會保存。系統或其他程式改變輸入來源不會更改守護目標；喚醒及解除暫停後會恢復目標。自訂 App／來源／裝置與明確關閉的功能設定保留；損壞設定安全停用，不覆寫原資料。

## 快捷鍵規則預覽

到「規則預覽」選擇 App、預覽 Profile 與按鍵來源，先看 Ctrl+C／Ctrl+Shift+C、Finder、瀏覽器、Alt+Tab、截圖等組合的預期輸出，也可選自訂組合。「模擬總開關開啟」只影響此頁，實際功能尚未啟用時也能預覽；不會改變已儲存的 App 規則、輸出按鍵或新增監聽。

Terminal 的 Ctrl+C 一律複製，不會因沒有選取內容而中斷命令；Ctrl+Shift+C 明確中斷。Remote／VM 使用 Windows 原始 Ctrl。來源欄表示抵達 Mac 的按鍵；已辨識來源的原始 Ctrl+C／X／V／A 共用剪貼簿規則，已是 Command 的按鍵保持原輸出。尚未辨識的事件來源不會猜測翻譯。預覽不代表已核准權限，也不模擬所有實體鍵盤／AX 焦點條件。

## 遠端來源校準

Apple「螢幕共享」連接另一台 Mac 時，接收端的 Bridge 會辨識 Apple 簽署的 ScreensharingAgent。自動模式把它傳來的原始 Ctrl 快捷鍵當作 Windows 操作轉換；已是 ⌘ 的 Mac 快捷鍵保持原樣。MacBook 的「MacBook 鍵盤模式」只交換該台內建 Fn／左 Ctrl；另一台 Mac 的遠端來源設定不會同步過去。雙向使用時，兩台各自安裝、授權，MacBook 開啟內建鍵盤模式，一般 Mac 保持關閉，並各測 Ctrl／Fn+C、V、Z。首次辨識未知來源的按鍵可能原樣通過，請放開所有鍵再測第二次；連續失敗時先檢查接收端遠端校準頁是否出現 ScreensharingAgent、權限與 Windows 模式狀態。

在 Windows 模式與必要權限啟用後，開啟「遠端校準」。先從遠端電腦送一個鍵到這台 Mac，確認來源列顯示「已觀察到此來源的輸入」，再按「開始校準」。保留設定視窗，切到這台 Mac 的 TextEdit 等文字 App，從指定遠端電腦按一次 Ctrl+C。App 只辨識這次 Control／Command 組合；60 秒內確認並套用結果，確認前原設定不變。

可取消、重新校準、手動指定來源按鍵或恢復自動判定；套用後可「還原校準前設定」。來源退出／重啟、暫停、Secure Input、權限或其他輸入政策改變都會取消未確認結果；正常本機 App 切換不會中斷測試。只偵測到遠端軟體不代表已收到輸入，也不代表所有連線組合已實機驗收。

## MacBook 與兩台 Mac

Mac mini 外接鍵盤固定不換；MacBook 只使用內建鍵盤，在 MacBook 開啟 Fn／Ctrl 模式，在 Mac mini 保持關閉。兩端都安裝 App、先使用一般模式，再按 [TwoMacAcceptance.md](TwoMacAcceptance.md) 分別測本機與 UC 兩方向。

原生映射使用 Apple 的 UserKeyMapping service properties；只修改本 App 擁有的 pair，保留其他工具。正常退出時先暫停輸入輔助，最多等待約 3 秒放鍵並確認還原；仍未還原會提供重試或取消結束，保留還原紀錄。關閉功能時也請放開所有按鍵。強制結束可能留下暫存映射，下次啟動依還原紀錄處理，重新開機清除服務暫存。喚醒與內建鍵盤重建會重新檢查。其他工具佔用 Fn／Ctrl 時顯示衝突，不覆蓋。

「已寫入映射」只表示服務屬性讀回一致，仍須在文字編輯反白測試文字，使用實體 Fn+C／X／V／A 確認複製、剪下、貼上、全選，並確認原本左 Ctrl 成為 Fn。若 Fn+C 仍開啟控制中心，而電腦正在使用 Karabiner，請檢查其 Devices：即使複合規則已停用，Modify events 仍可能接管內建鍵盤，改由虛擬鍵盤送出事件，繞過內建服務的映射。對內建鍵盤關閉 Modify events，保留外接鍵盤原設定後再測。虛擬鍵盤存在本身不證明接管；程式不會自動修改 Karabiner 設定或把交換表套到共用虛擬鍵盤。

`WindowsMacBridge --diagnose-backend` 可列出各鍵盤服務 Registry ID、class、內建／映射目標、服務回報的 Fn usage 與兩種映射表。此命令只讀取 metadata，不擷取實體按鍵，也不能代替上述實測。

UC 與 Remote 不是相同來源契約，來源 PID／目標 App 可能缺失；不能承諾每種組合都通過。已知 Google CRD host 的 raw Ctrl 依 Mac 目的端轉成 Command；已是 Command 的事件通過。Mac 上開遠端 Windows viewer 時保持 Ctrl，不要把 viewer 的 App 規則改成 Default macOS。未知來源不猜。

## 截圖權限與取消

第一次明確擷取才可能提出螢幕錄製要求；到「隱私權與安全性 → 螢幕與系統音訊錄製 → WindowsMacBridge」開啟。AX 無法替代這項授權。一般權限頁直接列出螢幕錄製入口，截圖失敗也會在一般設定顯示原因。

一般截圖使用 App 私有暫存 PNG，完成擷取後先寫入 public.png 剪貼簿，再產生自製縮圖，不等原生浮動縮圖消失或存檔。320×248 預覽顯示「截圖已複製」與貼上提示；圖片最長邊 720 像素。macOS 26+ 且建置 SDK 支援時使用 Liquid Glass，舊版使用毛玻璃。一般顯示 5 秒，滑鼠移入時保留，移出後重新計時；點圖後在目前螢幕中央開啟圖片預覽並取得焦點，可縮放或按 Ctrl+C 複製圖片，關閉預覽不清除剪貼簿。

預覽消失或圖片視窗關閉後清除自己的暫存原圖。只有 Win+PrintScreen 明確保存全螢幕 PNG 到桌面，必要時由 macOS 要求該資料夾存取；已存檔的圖片不隨縮圖消失刪除。App 不監看整個桌面或掃描舊圖，不改系統截圖偏好。需要原生標記與分享時使用 ⌘⇧5；本 App 功能開啟時的 ⌘⇧3／4 使用自製預覽，關閉後恢復系統原生行為。

Esc、Pause、功能關閉、backend／session／安全狀態或來源失效會取消舊工作；只有當前一輪能寫入剪貼簿，過期縮圖不會晚到覆蓋新預覽。同時最多一輪擷取，120 秒逾時。目前只處理截圖圖片，OCR 已停用。

目前版本不提供 OCR／文字辨識；截圖會複製圖片，可在圖片預覽中放大查看。

## 選配進階模式

一般設定 → 展開「進階選項」→ 明確勾選「解鎖進階後端模式」。之後才顯示後端、安裝／移除、Driver、指定鍵盤及詳細診斷。勾選本身不自動提權；選 HID 後，用面板的安裝按鈕準備背景元件，再逐項核准輸入監控與 Driver。所有安裝材料仍在同一 App，不要另外找 HID Helper.app。

系統 Driver 的官方名稱是 `.Karabiner-VirtualHIDDevice-Manager`；沒有自己的 Developer／DriverKit 簽署資格不能冒用或改寫該名稱。共用 Driver 不會因為退出一般模式或移除 WindowsMacBridge 的 root runtime 被刪除。切回一般模式先釋放硬件 ownership／關閉 XPC；舊 HID 確認停止之前，兩種後端都不翻譯，最多等 3 秒。只有背景元件回覆已停止、該連線從未擷取，或背景元件確定已結束，才算釋放；連線中斷或在期限內沒有回覆時，App 不推定鍵盤已釋放：選單顯示「Helper 未確認釋放鍵盤」，確認鍵盤正常後按「恢復／重啟引擎」。緊急暫停組合 Ctrl+Option+Command+P 會立即交還實體鍵盤。HID 斷線／Driver teardown 仍需實機驗收。

暫停可用選單列；暫停與正常退出會取消輸入輔助及未完成截圖。診斷只在進階模式明確開啟，5 分鐘到期，記錄規則／時間，不記錄輸入文字。
